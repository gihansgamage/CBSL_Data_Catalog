CBSL Data Workflow

Build the Data Catalog

1. The CBSL should establish a data catalog based on the existing data inventory. The catalog should be developed in two stages. The first stage should create a practical dataset-level catalog showing what data the CBSL holds, who owns each dataset, who can access it, and what it is used for. This should be delivered quickly because it directly addresses departmental need to find existing data and reduce duplicate requests. The second stage should expand the catalog² during platform implementation.

Footnotes:

  • A fuller catalog includes field-level detail (knowing what each field is, not just each dataset), data lineage (where each data point came from, so when there is a quality issue, it can be traced back), and validation rules (rules that travel with the data).
  • Generic Statistical Business Process Model: international framework for standardizing statistical production processes.

2. The first draft of the catalog should be built in three steps. First, the CBSL should normalize the existing inventory, agree what one catalog record represents, remove duplicates, and clean existing metadata. Second, it should complete partially filled fields, including contact point, description, division, classification, and internal shareability. Third, it should publish the catalog together with a simple request and overlap-check workflow. This work should be led by the DGU with support from departmental data stewards.

3. The catalog should be paired with a simple request and overlap-check workflow. Departments should first check the catalog to see whether the data is already collected elsewhere. If no overlap is found, the Director may approve the new collection under departmental authority. If overlap is detected, the DMC should assess value versus reporting burden, with escalation to the DMOC where needed. New datasets should then be registered in the catalog with a description, classification, owner, and access level. This workflow reduces duplicate requests on external intuitions in the short-term and gives departments visibility of what is already available across the CBSL (see Data Catalog and Request Flow Diagram of Appendix 1).
